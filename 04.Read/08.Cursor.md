# Cursor

- Let's say our query matches 10 million documents.
- Transferring 10 million documents over the wire from DB server to an app takes significant bandwidth and time. Those 10 million documents now reaches an application and can very well crash the app's memory. Now the app does the same thing to client. Also, it makes no sense for client to present 10 million documents to any user.
- When we run a find query, DB stores the results of the query in batches and gives us a pointer called cursor.
- That's why `find` method gives us a cursor on which we use following methods.


## count

- Returns the number of documents that match our query.
- If no query is provided, returns the count of all documents in our collection.
- [Docs](https://www.mongodb.com/docs/manual/reference/method/db.collection.count/)

```javascript
db.collection.find( { a: 5, b: 5 } ).count()
```

## sort

- I want to rearrange the documents based on a field value.
- 1 means ASC. 0 means DESC.
- For ASC, NULLS always comes first.
- [Docs](https://www.mongodb.com/docs/manual/reference/method/cursor.sort/#mongodb-method-cursor.sort)

```javascript
db.users.find({ }).sort( { age : -1, posts: 1 } )
```

## limit

- After query, sorting I got 1 million results. I want only n documents.
- [Docs](https://www.mongodb.com/docs/manual/reference/method/cursor.limit/#mongodb-method-cursor.limit)

```javascript
db.myColl.find().sort({_id: 1}).limit(10);
```

## skip

- From The result set after querying, skip n documents.
- [Docs](https://www.mongodb.com/docs/manual/reference/method/cursor.skip/#mongodb-method-cursor.skip)

```javascript
db.myColl.find().sort({_id: 1}).skip(3).limit(6);
```

> Order in which we chain sort, limit and skip does not matter. MongoDB optimises that for us.
