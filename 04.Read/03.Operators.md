# Operators

- I don't want equality comparison.
- In this case, we still write a query object with a key and a value. But value this time will be another object using some operator.

## Comparison

- Compare the document field's value with a provided value.
- [Docs](https://www.mongodb.com/docs/manual/reference/mql/query-predicates/comparison/)

```javascript
{ field: { operator: value } }
```

| Operator | Description |
| --- | --- |
| `$eq` | Matches values equal to a specified value. |
| `$gt` | Matches values greater than a specified value. |
| `$gte` | Matches values greater than or equal to a specified value. |
| `$in` | Matches any values specified in an array. |
| `$lt` | Matches values less than a specified value. |
| `$lte` | Matches values less than or equal to a specified value. |
| `$ne` | Matches all values not equal to a specified value. |
| `$nin` | Matches if the value is not equal to any of a given list of values. |


## Logical

- Chain multiple comparison conditions using OR, AND.

### [$or](https://www.mongodb.com/docs/manual/reference/operator/query/or/)

- Either rating is less than 3 or greater than 9.
- Combining two conditions. Either one should be true to select the document.
- Individually format of writing query stays the same.

```javascript
{ $or: [ { query1 }, { query2 } ] }
```

```javascript
{$or: [{"rating.average": {$lte: 5}}, {"rating.average": {$gte: 9.3}}]}
```

## $and

- By default if we write multiple fields in a query, it does an AND operation.
- But if want to add multiple conditions on the same field, this doesn't work. Because in JSON, adding existing key updates the value.
