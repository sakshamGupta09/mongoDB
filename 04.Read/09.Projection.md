# Projection

- Documents in a collection, might contain 100s of fields. Client only needs 10 of them.
- Sending all 100 fields means more data needs to be transferred over the wire causing more bandwidth, time and consume more memory resources.
- I want these fields only in my result set.
- By default, `_id` will always be part of the result set even if we do not include it in projection. We explicitly have to set it to 0 to remove it from response.

```javascript
const cursor = db
  .collection('inventory')
  .find({
    status: 'A'
  })
  .project({ item: 1, status: 1 });

```

```javascript
db.tvShows.find({}, {name: 1, genres: 1, "rating": 1, _id: 0})
```

## Projecting nested fields

- If we have an object with 3 fields and we want to include only 1.

```javascript
db.collection.find(query, {"top.field1":1})
```

## Arrays

```javascript
db.tvShows.find({genres: "Drama"}, {genres: 1})
```
- In this query we will get all array elements even though only Drama is the matching.

### First matching

- Return only the first matching array element even if multiple matches. Omit the rest from the resulting array.

```javascript
db.tvShows.find({genres: "Drama"}, {"genres.$": 1})
```
```javascript
db.tvShows.find(
  { $or: [{ genres: "Drama" }, { genres: "Action" }] },
  { "genres.$": 1 }
);

```
```javascript
db.tvShows.find(
  { genres: { $all: ["Drama", "Action"] } },
  { "genres.$": 1, _id: 0 }
);

```

## elemMatch

- I want this array field in the output only if any one element is matching the list of all queries.

```javascript
{ genres: "Drama" }, { genres: {$elemMatch: {$eq: "Horror"}} } 
```

## Slice

- I want only the first 2 values in the result set.

```javascript
{ genres: { $slice: 2} }
```
