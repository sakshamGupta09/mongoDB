# Why MongoDB

- When should we choose MongoDB over relational databases.


## 1. MongoDB shines when your data is naturally a document

- It makes more sense to store our data as one unit than splitting across multiple tables and then joining them to get the final output.


```json
{
  "name": "iPhone 17",
  "brand": "Apple",
  "price": 79999,
  "specifications": {
    "display": {
      "size": 6.3,
      "refreshRate": 120
    },
    "camera": {
      "main": "48MP",
      "front": "12MP"
    }
  },
  "variants": [
    {
      "color": "Black",
      "storage": "256GB",
      "price": 79999
    },
    {
      "color": "Blue",
      "storage": "512GB",
      "price": 89999
    }
  ]
}
```

- In MongoDB, this is basically one document. This entire thing is one product. Store and retrieve it as one unit.
- In a relational model, you might end up with:

```text
products
product_variants
product_specifications
product_cameras
```

## 2. Flexible schema

- Imagine you're building a marketplace where sellers can sell: phones, cars, clothes, laptops, furniturte.
- Their attributes are completely different.
- With MongoDB, these can naturally live in the same collection.
