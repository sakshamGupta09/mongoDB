# Terminology

- Any DBMS relational or NoSQL has a DB server. We first connect to the server and then ask server to do stuff for us. A server can have multiple DBs.
- A DB has collections. Collections are tables in SQL world.
- A collection has documents. Documents are like rows in SQL table.


## Document structure

- A Document is always a JSON object.
- When we insert a document into collection, we insert a JSON.
- When we read from collections, we get back documents which are JSON.

## BSON

- MongoDB internally stores our document as a BSON because it is more efficient and supports some additional types than JSON like ObjectId.
- We always deal with JSON. When we run insert command, we provide a JSON as document. When we read we get back JSON as documents.
- Drivers are responsible to convert our JSON to BSON and BSON to JSON.


## Implicit collection creation

- In SQL world, before we perform CRUD operations, we need to create tables and define schemas.
- In MongoDB, You don't need to explicitly create a collection before inserting documents. MongoDB creates it automatically when you first use it.
- MongoDB follows a "create when first used" approach, reducing upfront schema/setup work.

## Shell vs Drivers

- Goal is to connect with our DB server.
- To connect to our local MongoDB server, we can use shell.
- When we create our backend server, we want our application to be able to connect to the DB server. For that we have drivers for different programming languages.
