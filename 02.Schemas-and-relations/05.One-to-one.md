# One to one relations

## Embedding makes more sense

- User ↔ Address
- A user's address is usually tightly coupled to the user and is read together.
- Address belongs to that user.
- Usually fetched with the user.
- No need to query the address independently.
- Simple and efficient.

```javascript
{
  "_id": 101,
  "name": "John",
  "address": {
    "street": "MG Road",
    "city": "Hyderabad",
    "pincode": "500001"
  }
}
````

## Reference makes more sense

- Employee ↔ EmployeeProfile
- Suppose the profile contains large/independently managed information such as documents, preferences, settings, etc.
- Profile has its own lifecycle.
- It may be accessed/updated independently.
- It could become large.
- You may not need the profile every time you fetch an employee.

```javascript
employees
{
  "_id": 101,
  "name": "John",
  "profile_id": 501
}

employee_profiles
{
  "_id": 501,
  "employee_id": 101,
  "preferences": {...},
  "documents": [...],
  "settings": {...}
}
```
