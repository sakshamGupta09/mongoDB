# One to Many Relation

##  Embedding makes more sense

Order → Order Items

- Items belong specifically to this order.
- Usually read together with the order.
- Order items don't have an independent lifecycle.
- The number of items is reasonably bounded.
- One query retrieves the complete order.

```javascript
{
  "_id": "order123",
  "customer": "John",
  "items": [
    {
      "product": "Laptop",
      "quantity": 1,
      "price": 80000
    },
    {
      "product": "Mouse",
      "quantity": 2,
      "price": 1000
    }
  ]
}
```

## Reference makes more sense

Customer → Orders

- Number of orders can grow indefinitely.
- Orders have their own lifecycle.
- Orders are frequently queried independently.
- You don't want the customer document growing forever.
- You may need to query/paginate orders separately.

```javascript
customers
{
  "_id": 101,
  "name": "John"
}

orders
{
  "_id": 5001,
  "customer_id": 101,
  "total": 85000
}

orders
{
  "_id": 5002,
  "customer_id": 101,
  "total": 12000
}
```
