# Data modelling

- This is a core step in building any new project or feature.
- What kind of data this feature will generate. How to store that data. What are the entities and their attributes. How are different entities related and how to map that relationship.


## Schema

- Though MongoDB doesn't enforce us to have a schema, it's always useful to have some rules and constraints so that right data enters in our database.
- An Entity must have some core attributes and each attribute should be of a particular type. It can have other attributes as well but the mandatory ones should be there and in the right format.
- Incoming data will be validated against these rules and constraints and will be allowed only if it passes the validation.

## Approaches

- One way is that every document in a collection must have same structure. We use `NULL` to indicate lack of information but field must exist.
- Another way can be to have no schema at all and hence each document can be completely different than the other.
- A practical approach though is to have some core attributes that must be present for every document and then each document can some some additional information if available. If not, we omit the field completely instead of storing `NULL`.
