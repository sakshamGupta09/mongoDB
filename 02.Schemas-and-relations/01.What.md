# Data modelling

- This is a core step in building any new project or feature.
- What kind of data this feature will generate and how to store it in a right manner that allows faster reads and writes.


## Schema

- Schema defines the structure of our collections, what fields it should have and what values are acceptable.
- Though MongoDB doesn't enforce any schema, it's always useful to have some rules and constraints defined so that right data enters into our database.

## Approaches

- One way is that every document in a collection must have same structure. We use `NULL` to indicate lack of information but field must exist.
- Another way can be to have no schema at all and hence each document can be completely different than the other.
- A practical approach though is to have some core attributes that must be present for every document and then each document can some some additional information if available. If not, we omit the field completely instead of storing `NULL`.
