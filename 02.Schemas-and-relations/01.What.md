# Data modelling

- This is the core concept for any new project or feature.
- What kind of data this feature is generating. What are the entities and their attributes. How are different entities related and how to map that relationship.


## Schema

- Though MongoDB doesn't enforce us to have a schema, it's always useful to have some rules and constraints so that right data enters in our database.
- In SQL world, every row should have same structure. MongoDB can have two completely different documents in the same collection. We can use the best of both worlds, where we define mandatory attributes and then be open to have some optional fields to utilize MongoDB's flexibility.
- An Entity must have some attributes and each attribute should be of a particular type. It can have other attributes as well but the mandatory ones should be there and in the right format.
- Incoming data will be validated against these rules and constraints and will be allowed only if it passes the validation.
