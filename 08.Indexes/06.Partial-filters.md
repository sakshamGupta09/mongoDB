# Partial Filters

- Do not store all the values of a field in an index. Because we are mostly querying for specific set of values only.
- It makes our index smaller in size and faster to search.
- MongoDB knows when the index is not sufficient to return all results and can perform collection scan in those cases.

## Examples

### 1. Active users only

- Suppose you have millions of users, but you frequently query only active users:

```javascript
db.users.createIndex(
  { email: 1 },
  { partialFilterExpression: { status: "active" } }
)

db.users.find({
  email: "john@example.com",
  status: "active"
})
```

### 2. Soft-deleted records

```javascript
db.projects.createIndex(
  { organizationId: 1, name: 1 },
  {
    partialFilterExpression: {
      deletedAt: null
    }
  }
)
```

### 3. Calculate retiral income

- Our platform allows a feature for people colse to retirement. In that case we should only store age values greater than 60.

### 4. Index optional fields

- We create a unique index on email, and email is optional field.
- We insert first record with no email.
- If we now insert another record with no email, it will complain.

```javascript
db.collection.createIndex(
  { email: 1 },
  { unique: true, partialFilterExpression: { email: { $exists: true } } },
);
```
