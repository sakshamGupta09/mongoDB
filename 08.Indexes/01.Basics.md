# Indexes

- We have a collection with 100 million documents and our query just returns fraction of them like 10 or 100.
- MongoDB does a `COLLECTION` scan where it checks every document one by one.
- This can take considerable amount of time. We scanned 100 million documents just to get 10 back.
- We need a better way to find limited documents in a very large collection.

## What

- Identify which fields are used frequently to query a collection.
- Store the values of that field in an ordered way with a pointer to the original document. It's so much faster now to search in ordered list.
- Our queries first will go to this index and quickly find the keys. This is called `IXSCAN`.
- After this, we go to the original document to get additional fields. This is called `FETCH` stage where we return documents.

## Don't overuse indexes

- It can slow down write queries as new document needs to be inserted/updated in the index data structure as well.
- It takes memory.

## Does indexes always speed up read queries?

- Indexes are useful only when we retrieve a small subset of documents from a big collection.
- However, if we are retrieving majority of documents in our query, then index won't be of much help because after `IXSCAN` we have a `FETCH` stage.
- Only use indexes when we are reading subset of documents.
