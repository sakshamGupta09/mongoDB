# Indexes

- We have a collection with 100 million documents and our query just returns 10 or maybe 100 of them.
- When we do a read query, MongoDB goes does a collection scan. It goes to every document one by one and sees if it fulfils the criteria.
- This can take considerable amount of time. We scanned 100 million documents just to get 10 back.

## Why

- To speed up read, update and delete queries.
- Provide a better way to find limited documents in a very large collection.

## What

- An index is a data structure that holds all the values of a field in an ordered way. Each node has a value and a pointer to original document.
- When we write a query, it first goes to index data structure and since it is ordered, it's efficient to search here. This is called IXSCAN which returns key and pointer.
- Once we find result from an index, we go to the original document to get additional fields. This is called FETCH stage where we return documents.

## Don't overuse indexes

- It can slow down write queries as new document needs to be inserted/updated in the index data structure as well.
- It takes memory.

## Does indexes always speed up read queries?

- Indexes are useful only when we retrieve a small subset of documents from a big collection.
- However, if we are retrieving majority of documents in our query, then index won't be of much help because after IXSCAN we have a FETCH stage.
- Only use indexes when we are reading subset of documents.
