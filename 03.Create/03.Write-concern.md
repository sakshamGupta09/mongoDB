# Write Concern

- We send a write request to DB server and want status of our request from server - success or error.
- We want to control when should MongoDB server send us the confirmation.

```javascript
db.collection.insertOne({}, { writeConcern: { w: 1, j: undefined, wtimeout: 200 } })
```

## Problem

```text
             ┌── Primary
Application ─┤
             ├── Secondary 1
             └── Secondary 2
```
- MongoDB has replica sets. The primary receives the write and replicates it to the secondaries.

```javascript
db.users.insertOne({ name: "Saksham" })
```

- What does definition of success looks like in this case? We have following options.

## What does w actually mean?

- Number of replica-set members that must acknowledge the write.
- Has the data reached enough MongoDB members.


## { w: 1 }

- Tell me success once the primary has received the write.
- The secondaries don't have to acknowledge before your application gets success.
- If the primary crashes immediately afterward before replicating the write, that write could potentially be lost during a failure scenario.
- Default


## { w: "majority" }

- Tell me success only after a majority of the members have received the write.
- MongoDB waits for enough replica-set members to acknowledge.


## { w: 0 }

- I don't want any response back from MongoDB server. No success, no error.
- This can reduce latency, but you don't get normal write acknowledgment/error reporting.
- Used when it's okay if we lose some data.


## Storage journal

- When we send a write to DB server, it ultimately needs to update the files on the disk which takes time and is error prone.
- If some crash happens in between we lose our write.
- So, we first make an entry in the journal. If our system crashes, it can read the journal and re perform the operations. It's like a TODO list
- I want confirmation when you have entered this write in the journal. Default - undefined.

```text
                 MongoDB
                    │
              "I need to write"
                    │
                    ▼
              ┌──────────┐
              │  Journal │  ← durable record of the change
              └──────────┘
                    │
                    ▼
              Main data files
```
If the machine crashes:

```javascript
Journal:
"These changes were supposed to happen."

        ↓ restart

MongoDB replays the journal
        ↓
Database recovers
```

## wtimeout

```javascript
{ w: "majority", wtimeout: 5000 }
```

- Wait up to 5 seconds for a majority to acknowledge my write. If that doesn't happen, stop waiting and report a timeout.
